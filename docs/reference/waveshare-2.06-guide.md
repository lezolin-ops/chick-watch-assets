## 2. 硬件速查

**官方资料（S1）**：ESP32-S3R8，8MB PSRAM、32MB Flash；410×502 CO5300 AMOLED；FT3168触摸；AXP2101；QMI8658C；PCF85063；ES8311/ES7210音频链路。电池接口为3.7V MX1.25。

| 链路 | GPIO |
|---|---|
| 显示QSPI | 数据4/5/6/7，时钟11，片选12，复位8，TE 13 |
| 共享I2C | SCL 14、SDA 15；触摸/PMU/IMU/RTC/音频共用 |
| 触摸 | INT 38、RESET 9 |
| IMU / RTC中断 | 21 / 39 |
| SD | MOSI/CMD 1、CLK 2、MISO/D0 3、CS 17；实际总线模式按例程核对 |
| 音频 | MCLK 16、BCLK 41、LRCK 45、播放40、采集42、功放46 |
| USB / UART0 | USB 19/20；UART TX 43、RX 44 |
| 按键 | BOOT 0，按下低；PWR相关SYS_OUT 10，运行时按下高 |

PWR长按约6秒硬件关机，关机后单击开机，关机仍可充电。BOOT按住再上电用于下载恢复。共享I2C必须避免重复建总线及地址冲突；GPIO0为启动配置脚，19/20复用会影响USB。依据S1、S7。

**项目约束**：圆角不是全矩形可见区域；使用项目的[安全区依据](../../firmware/DISPLAY_SAFE_AREA.md)及[UI规范](../design/watch-ui-ux-guidelines.md)。111px加8px是当前参考模型，不是面板实测结果。项目Flash/PSRAM启动核验记录见[产品记录](../../PRODUCT_UPDATES.md)，本次没有重新连接设备测量。

## 3. 开发环境与示例选择

### ESP-IDF路线（S5）

官方当前说明推荐IDF ≥5.5、LVGL 9.5.0和本型号BSP。每个示例是独立工程；入口为main，清单/锁文件控制依赖，defaults和分区表控制内存/空间。切换版本需清理构建并核对配置；首次依赖失败先查网络。

| 示例 | 用于隔离验证 |
|---|---|
| 01_AXP2101 | PMU/I2C；AXP地址0x34；无屏幕 |
| 02_lvgl_demo_v9 | CO5300、FT3168、LVGL基础显示/触摸 |
| 03_esp-brookesia | 复杂应用系统、显示锁、资源/内存 |
| 04_Immersive_block | IMU、水平校准、圆角运动边界 |
| 05_Spec_Analyzer | 音频采集及频谱 |
| 06_videoplayer | TF卡、MJPEG+PCM；视频画布320×200 |

官方建议先01、02，再04、05、06，最后03。PMU例程周期处理状态，不代表已经实现低功耗睡眠。运动示例采样参数是演示选择，不能直接作为手表省电设置。

### Arduino路线（S4）

Arduino-ESP32 ≥3.2.0；板型ESP32S3 Dev Module，32MB Flash、OPI PSRAM；自写Serial需启用USB CDC。使用仓库匹配库及pin_config/lv_conf；当前说明为LVGL 9.3.0，不能混用2.16的LVGL8配置。

01文字、02字符表验证显示；03 RTC；04 IMU；05 AXP电压/状态；06 LVGL控件/触摸；07 SD_MMC 1-bit卡测试；08音频播放及回环。显示示例有22像素列偏移，移植时核对驱动是否已处理。RTC示例每次启动写固定时间，产品必须改成有效时间读取/校时。错误日志中的PCF8563名称不代表本板换成该芯片。音频示例文件名有canon/canon.h与目录描述差异，以实际仓库文件为准。

### 出厂与AI功能（S3、S6）

出厂Brookesia有绘图、频谱、重力球、图库、媒体、设置和AI应用；底部上滑退出，上滑停留看最近应用；设置有网络、亮度、音量、电池ADC。恢复包说明的0x00地址只适用于相应完整镜像，不能用于本项目应用bin。

AI页列出小智/OpenClaw/ESP-Claw教程入口；本型号列为小智v2.4.2适配。该列表不是当前宠物固件的功能或版本。更换第三方/出厂固件前保护当前备份和NVS。

## 4. FAQ中影响开发的结论

**官方参考（S7）**：建议42728、400mAh电池；满亮约1小时、仅关闭亮度约3～4小时、全低功耗约6小时。未完整给出负载/软件/睡眠条件，不能作为当前固件承诺。百分比受负载、插拔充电及老化影响；应结合电压判断，不能仅用瞬间掉百分比证明容量消耗。

官方建议部分场景使用低功耗模式。FAQ温度实验条件为20℃室温、Wi-Fi STA+AP并充电，PMU温度最高46℃；这是特定实验，不能当安全阈值或电池温度。标称屏亮600nit，0x51参数0～255控制亮度；不防水。3.3V外接负载建议50mA以内。中文需要UTF-8、字体字形及显示库支持。FAQ旧LVGL9.2转8.3说明与当前IDF/Arduino版本说明不同，不能覆盖项目版本。

官方不提供外壳3D文件，产品是开发板；代码改造由开发者完成。其他串口、SquareLine及恢复问题按对应来源查询。

## 5. 与当前项目的差异（本地代码核对）

下列是2026-10-13工作区代码现状，不能推定设备已经刷入完全相同版本。

| 项目 | 本地证据 | 后续含义 |
|---|---|---|
| 依赖 | `firmware/main/idf_component.yml`：BSP ^2.0.0，LVGL ^9.6.0 | 项目已偏离官方示例LVGL；精确版本查dependencies.lock，不为对齐网页盲目降级 |
| CPU | `firmware/sdkconfig`：240MHz，PM_ENABLE未启用 | 没有配置系统动态降频；启用后另测动画、SPI、I2C稳定性 |
| 黑屏 | `watch_clock.c`加载黑屏并调用backlight_off | 未调用CPU睡眠，也未证明面板休眠 |
| 亮度接口 | 当前BSP的backlight_off仅调用brightness_set(0)，后者发送0x51 | AMOLED没有传统独立背光，接口命名不能证明断电/休眠 |
| 按键 | `watch_clock.c`每100ms读取PMU短按状态 | GPIO10为官方可检测路线，能否用于目标睡眠唤醒仍需验证 |
| 宠物暂停 | `pet.c`暂停三个宠物定时器 | `pet_scene.h`云33ms、风40ms定时器没有被该函数暂停，后台仍可能做计算 |
| 其他周期任务 | 设置50ms、时钟1s；LVGL Port周期tick | 仅暂停宠物无法消除所有唤醒，应完整审计 |
| Wi-Fi | MIN_MODEM；启动默认开启，失败状态约30s重试 | 已有无线基础省电，但无线持续开启；按需断网是新行为建议 |
| 显示补丁 | `firmware/patches/README.md` | QSPI完成回调、内部DMA行缓冲及固定竖屏内存调整必须保留 |

当前BSP头文件还残留其他板型/器件注释；BSP能力宏（例如IMU=0）只描述软件封装，不能据此断言本板无IMU。核对官方器件表、实际引脚定义和初始化路径。

## 7. 续航优化与验证入口（提议，未实现）

微雪FAQ推荐低功耗，但本次已读产品文档没有提供可直接证明本项目续航的完整睡眠方案、电源支路关闭表或实测待机电流。动态降频/自动轻睡眠机制另查[乐鑫ESP32-S3电源管理](https://docs.espressif.com/projects/esp-idf/en/latest/esp32s3/api-reference/system/power_management.html)，开发时选择与本项目IDF一致的文档版本。

建议顺序：测量基线→暂停隐藏场景任务→动态降频→息屏轻睡眠→按需无线→按原理图关闭闲置外设支路。Wi-Fi校时后自动关闭会改变PU-013持续联网行为；本次没有确认替代该决策。深睡眠醒来会重新启动应用，需要额外处理状态保存和恢复。

自动轻睡眠需要PM配置与tickless idle，驱动的电源锁、周期计时器和无线状态会影响实际睡眠时间。不能仅开启配置便报告“已经省电”。GPIO10的按键检测电平不等于已验证唤醒：先测空闲/按下电平、短按脉宽、充电和电池状态，再核对唤醒能力、配置和长按关机。先前泛称“改PMU中断唤醒”只是设想，未核实可用IRQ引脚；禁止猜用GPIO35或其他内存占用脚。

| 电流 | 电池侧平均与峰值、采样窗口/仪器；USB输入电流不能直接等同电池放电电流 |
