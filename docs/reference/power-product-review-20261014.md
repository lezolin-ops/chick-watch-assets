# 续航优化：产品取舍报告

2026-10-14。当前结论：第一轮已经完成代码、模拟测试及真机启动检查，**尚无电池侧功耗数据，不能可靠填写“每项增加几小时”**。USB连接期间不能以电量变化证明续航收益；容量未知不妨碍后续等时电流比较。

## 优先级与取舍

| 优化点 | 目前证据 | 每项续航提升 | 建议与代价 |
|---|---|---|---|
| 停止隐藏动画计算 | 云/草花停止，10秒模拟无后台刷新，恢复通过 | 未实测 | 建议保留，体验代价小 |
| 取消高频tick并降频 | 5ms周期源停止；空闲80MHz，最高240MHz，真机初始化通过 | 未实测；200次/秒→0仅是该周期源，不是续航比例 | 建议保留；动画/交互速度再做佩戴验收 |
| 黑屏轻睡眠 | 配置、黑屏状态切换通过；USB会阻止实际睡眠 | 未实测 | 优先验证电池待机收益和真实唤醒，需与前两项配合 |
| 休眠后关闭Wi-Fi | 临时版日志验证停止无线；最终已改为默认保留，提供配置接口和后台需求保护 | 未实测 | 可选，连接即时性与省电交换；设置开关留待确认 |
| 屏幕/触摸真正休眠 | 官方序列已查；当前仍仅亮度零 | 未实施/未测 | 下一轮独立实验，注意唤醒恢复与延迟 |
| 外设断电、深睡眠、调整亮度/超时 | 未实施 | 未测 | 暂缓，先看前几项数据，避免改动过多影响产品体验 |

“值得优先验证”不等于“已经证明明显延长续航”。单项不能简单叠加，最终组合必须另测。默认保留最高亮度与原按键/息屏行为，正式交付继续无损压缩素材。

## 早上的最短验证路径

1. 电池状态做PWR/BOOT、息屏后显示与触摸恢复检查。
2. 固定10分钟黑屏，旧基准与新版各测一次，Wi-Fi都保持连接，确认组合收益。
3. 再在同配置下比较Wi-Fi保持/关闭，分离网络策略收益。
4. 若组合值得保留，再按独立开关拆分降频、tick、轻睡眠和隐藏动画；不做完整放电。

有电池侧平均电流时：耗电减少 `1-I新/I旧`；相同使用模式的条件性续航倍率 `I旧/I新`。旧版同模式实际续航T未知时不换算增加小时；只有电压/百分比时只报告变化，不推出倍率。测试工具会拒绝USB供电或时长不匹配的数据。
