# Bangle.js 软件计步移植

2026-10-19（Asia/Shanghai）。状态：**已实现（待真机验收）**。1.2.0候选固件已编译并于同日用户授权后刷入，92秒启动/息屏后读取通过。不能把源码测试或外部数据回放当成本手表计步、精度或功耗验收。

## 选择与实现

用户确认目标为移植简单、准确稳定、耗电少，并授权开工。第一阶段采用Bangle.js现有C算法，保留默认滤波、活动门限、步间隔和连续6步补记；不新增陀螺仪融合。选择基于可复用代码、实际手表集成和回放工具，并不证明它在本设备优于所有算法。停止继续调内置计步参数，不据此宣称所有QMI8658C均无硬件计步。

- 上游固定修订与MPL-2.0说明：[vendor README](../../firmware/main/third_party/bangle_stepcount/README.md)。原始源码与固定修订逐字节一致后移植，仅替换整数平方根依赖、补全重置时活动门状态的清理。
- 依赖保持ESP-IDF5.4.2、BSP2.0.0、LVGL9.6.0~1、LVGL Port2.9.0。三个板级补丁反向检查通过；没有替换组件。
- 唯一worker使用共享I2C14/15，读取0x30起11字节（时间戳、温度占位、三轴加速度）。QMI设±2g、62.5Hz、LPF mode2（按本地SensorLib定义为5.39% ODR，约3.37Hz）；陀螺仪和内置计步/运动引擎关闭，禁用data-ready中断。该滤波选择需真机评估，不是已校准参数。
- 每80ms读取最近样本形成12.5Hz算法输入：16384/g转8192/g，64位计算平方和。传感器内部更新与主控读取非同步，当前不是FIFO连续采样，也不是将所有62.5Hz样本重采样；时序及精度需要实测。
- 主控按单调时钟目标安排读取，不集中补发错过的样本。间隔小于40ms/大于120ms、重复或倒退的24位传感器时间戳重置识别状态，跳过该样本；正常时间戳回绕接受。I2C失败清识别状态、保留日累计，后续成功读取恢复。
- 可接管项目已知的旧硬件/官方适配配置和新软件配置；未知活动配置拒绝。配置写入逐字节读回；初始化失败尽力恢复原控制寄存器并释放客户端/设备，运行重配失败停止任务并释放电源需求。
- 沿用pet_steps日累计/366日历史、60秒有变化才保存、日期回拨保护、保存失败重试和正常重启保存；不变更NVS格式。确认阶段待补记的最多5步属于RAM算法状态，重启/采样间断会丢弃，不把中断前后动作串联。跨日附近批次可能有少量日期归属偏差。
- UI布局、触摸/按键语义与刷新频率未改。只有实际读数、计算和存储时持WATCH_POWER_AWAKE，等待释放；Wi-Fi策略不变。相比旧硬件方案每2秒轮询，当前每80ms唤醒一次，不能声称总功耗已下降。FIFO批量读取为后续候选，尚未实现。

## 按需诊断与回放

- `STEPS_STATUS`：单次软件累计、样本数、间断数、读错误数、XYZ及时间戳。
- `STEPS_REINIT`：唯一worker重配传感器/重置算法，保留日累计；失败停止worker，需要重启恢复。
- `STEPS_CAPTURE`：显式开启60秒采样CSV，自动结束。开始时清识别状态便于独立回放，不清日累计；会丢弃尚未确认的短步串。日志会增加负载，不用于正式功耗对比。
- CSV：`STEP_SAMPLE,host_us,sensor_timestamp,raw_x,raw_y,raw_z,delta,reset_or_gap`。reset/gap行作为新基线且不计步。
- 软件构建拒绝旧STEPS_FORMAT实验；官方诊断构建保持独立，CMake只选一个worker，避免并发访问。

工具：`python3 firmware/tools/replay_steps.py capture.log --format capture`，使用本次相同C代码编译动态库，逐样本核对固件delta，发现不匹配返回失败。采集必须完整，工具拒绝畸形行和倒退的主控时间；不从没有采集的时段猜测运动。

上游数据：`python3 firmware/tools/replay_steps.py INPUT.csv --format upstream --expected N`。默认保留原记录时间间断；`--nominal-cadence`仅用于模拟上游测试工具按每行一个固定周期处理的方式。不能把忽略时间间断后的结果当真实丢采样下的性能。
