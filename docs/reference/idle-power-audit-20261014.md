# 黑屏与闲置外设只读排查 · 2026-10-14

本轮未刷机，未写芯片供电/充电/外设配置。读取工作区与本地官方组件源码，并通过现有日志功能重启导出219条历史。没有新增I2C诊断固件，因此未直接读取IMU/Codec运行寄存器、功放GPIO电平或屏幕状态寄存器。以下区分调用链证据、历史遥测与待测硬件状态。

## 历史诊断的证据与限制

本次完整导出219条。14条同时满足“黑屏、诊断字段有效、未标记USB或充电”的样本；其中12条睡眠路径比例92%，其余24%和2%。这些样本约16:55～17:37，百分比却从68%回升到80%，存在充电后估计恢复、供电状态或电量估计算法等不确定性，不能当稳定纯放电样本或计算省电收益。

sleep_path_percent取IDF sleep退出回调提供的路径耗时，包含进入/退出及拒绝调用开销；不等同精确成功睡眠占比。只能支持“休眠路径确实运行过”，不能写成“CPU成功休眠92%、整机节电92%”。USB期间成功/拒绝计数均0、USB NO_LIGHT_SLEEP锁持有是已知预期。下一轮需要电池态区间的成功次数/拒绝次数与电流数据，才能细化。

- 同BSP `bsp_display_start_with_config`只走LVGL、显示、触摸、亮度；音频函数定义不能作为已初始化证据。
- `esp_lcd_sh8601.c`第334行disp_on_off仅发DISPON/DISPOFF，不能把接口名称当sleep-in实现。当前BSP使用SH8601兼容驱动控制CO5300，睡眠指令/延时必须核对实际面板资料。
- `watch_settings.c`每50ms BOOT检查，`watch_clock.c`100ms PMU按键检查、1秒时钟/记录门控；宠物隐藏定时器已有暂停。
