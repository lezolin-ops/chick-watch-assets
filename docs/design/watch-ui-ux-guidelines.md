# 电子宠物手表 UI / UE 设计规范

版本：v1.0 · 更新日期：2026-10-12 · 适用设备：微雪 ESP32-S3-Touch-AMOLED-2.06 方形手表套件。

本规范是后续界面设计、交互实现和视觉验收的统一入口。UI 指视觉与控件，UE 指使用流程、反馈和操作体验。设计图、模拟器和真机均须遵循。

## 1. 规则等级与使用方法

| 标记 | 含义 |
|---|---|
| 必须 | 已确认的产品约束或本规范要求，新开发不得遗漏 |
| 建议 | 默认设计方向，可根据页面用途调整并说明理由 |
| 待验证 | 参考值或未验收能力，不得写成硬件定值或已上线 |
| 当前实现 | 描述实际固件行为，不保证已经通过全部人工验收 |

新增页面先读本规范与[产品更新记录](../../PRODUCT_UPDATES.md)。与历史设计稿冲突时，以用户最新指令和明确的后续产品决策为准；无法确认的差异应记录，不能自行冒称已统一。修改规则时同步更新本规范、关联页面说明及产品记录。

规范的创建不会自动修改固件。文中“建议”和“未来流程”需要另行实现及验收。

## 2. 设计目标

- 宠物是主角；设置和状态信息为陪伴体验服务，避免用装饰性仪表抢占空间。
- 小屏一次完成一个主要任务，每页有清晰标题、主要操作和返回路径。
- 信息真实：显示实际连接、保存和更新状态，不能用演示结果替代真实功能。
- 操作可预期：同一按键、返回图标和控件在不同页面含义一致。
- 以手表实际可见区域与触摸体验判断好坏，不以桌面大图看起来完整为验收依据。

## 3. 硬件、坐标与圆角安全区

### 3.1 硬件基线

| 项目 | 统一基线 | 状态 |
|---|---|---|
| 型号 | ESP32-S3-Touch-AMOLED-2.06 方形手表套件 | 用户确认 |
| 屏幕 | 2.06英寸 AMOLED，圆角矩形 | 用户照片确认形状 |
| 逻辑画布 | 410×502，竖屏，坐标从左上角开始 | 当前实现 |
| 输入 | 电容触摸、BOOT、PWR | 当前实现 |
| 屏幕圆角模型 | 官方Demo换算约111px | 参考模型，非面板实测 |
| 额外安全余量 | 8px | 当前布局校验标准，待真机校准 |

拍照时设备或照片旋转，不等于固件需要改变显示方向。涉及显示/触摸旋转时必须同时核验映射；不要拿其他微雪尺寸或圆屏的参数直接套用。

### 3.2 必须避开物理圆角

410×502是矩形地址范围，四角并非全部可见。全屏背景可延伸至边缘，但文字、图标、密码、操作按钮和触摸目标必须完整落在安全区内。

- 检查整个控件及可点击区域，不能只检查中心点。
- 24px左右边距只是中部参考；不能保证靠近上下四角的控件安全。
- 返回按钮、底部确认按钮、键盘最后一排和弹出按键都必须检查。
- 控件阴影、焦点边框、动画位移和时钟移位也要计入可见范围。
- 滚动列表可有明确的部分行裁切，但固定操作不得被裁切；列表中的关键文字在滚入可用区域后必须完整可读。
- 增加软件圆角或把按钮画圆，不能代替物理安全区布局。

当前模型的公式、来源和坐标详见[屏幕安全区](../../firmware/DISPLAY_SAFE_AREA.md)。官方Demo使用9.2mm圆角参数，并取横纵像素密度的较小值换算为111px；不可将按钮的样式radius当成面板半径。用户照片存在透视，不能据此宣称完成精确半径测量。

### 3.3 当前可复用布局参考

以下是设置页修正后的参考，单位px；它们不是所有页面必须机械复制的模板。

| 元素 | x / y | 宽×高 | 使用要求 |
|---|---|---|---|
| 返回按钮 | 56 / 40 | 48×48 | 图标和完整触摸区域均避开左上角 |
| 标题 | 120 / 50 | 234×实际文本高度 | 长标题换行或精简，不与返回按钮重叠 |
| 正文容器 | 24 / 94 | 362×380 | 容器内子元素仍须逐项检查安全区 |
| 密码键盘 | 24 / 210 | 362×230 | 底边440，保留四行及圆角余量 |

禁止恢复旧返回按钮(18,20)的位置；用户照片已证明该位置发生裁切。

## 4. UI视觉规范

### 4.1 色彩与可读性

系统设置采用深色AMOLED界面，使用少量浅绿色突出主要动作。宠物场景可以沿用既有美术色彩，不强行套用设置配色。

| 用途 | 当前参考色 | 规则 |
|---|---|---|
| 设置背景 | `#090B0B` | 接近黑色，避免大面积高亮底色 |
| 普通正文 | `#F3F5F2` | 与实际控件背景共同检查 |
| 密码文字/遮掩圆点 | `#FFFFFF` | 隐藏与显示模式均明确设置为白色 |
| 次要提示/占位文字 | `#A9B0A4` | 占位提示不能替代错误信息 |
| 控件背景 | `#252B24` | 区分可操作区域，勿靠深浅微差表达唯一状态 |
| 主要动作背景 | `#B5CF83` | 使用深色文字`#182111`，避免浅色字配浅底 |

必须明确设置输入框的文字、背景和相关状态颜色，不能依赖父级继承：此前密码难辨即与控件样式继承有关。检查正常、按下、禁用、聚焦和错误状态；不能只看空输入框。

状态表达同时使用文字或图标，不能只靠颜色。正式产品界面不显示FPS、CPU、内存等开发叠字；调试模式另行明确开启。

### 4.2 字体与文案层级

| 场景 | 当前实现/参考 | 后续设计要求 |
|---|---|---|
| 设置正文/键盘 | 24px基础字体 | 保持清晰，避免为塞内容不断缩字 |
| 新页面标题 | 建议28–32px；现有设置标题24px | 与正文有清晰层级，先满足安全区 |
| 次要文字 | 建议20–24px | 必须在手表正常观看距离检查 |
| 时钟时间 | 48px字形放大，约96px视觉字号 | 保留横排，不显示秒数 |
| 时钟日期、电量 | 当前约32px、36px视觉字号 | 独立时钟规范，不强制所有设置字都达32px |

字号建议不是已经实现的统一升级。字形放大后应按实际包围盒检查，不按原始字号估算宽度。

- 中文主界面使用简短自然文案，避免把寄存器、分区等实现细节呈现给用户。
- 网络名称等用户数据不得擅自翻译；长名称换行、省略并提供完整查看方式。
- 必须检查中文、拉丁字符、数字、标点和符号是否有字形。当前字体子集可能缺少任意中文SSID，这一限制仍待完善。
- 图标配可理解文案；眼睛按钮、返回图标等独立操作须有明确语义。
- 错误写清结果和下一步，例如“认证失败，请检查密码”，不要只写“Error”或猜测一定是密码错。

### 4.3 布局与控件

- 一页优先只有一个主要动作，次要动作视觉降级。
- 保持标题、列表、输入框和按钮对齐；优先调整结构，而不是整体缩小画面。
- 建议普通独立触摸目标至少48×48px；间距留出防误触余量。
- QWERTY首行十键受362px宽度约束，键宽约三十余像素，无法做到每键48px宽。键盘属于明确例外：保持尽可能大的键高、分隔、放大反馈，并用真机连续输入验证；不得宣称所有键达到48×48。
- 固定底部按钮必须上移避开圆角；不要把主要动作藏在长列表末尾。
- 滚动只用于有必要的列表或内容；设置首页当前三项保持一屏；新增桌面时钟开关设计采用四项一屏（未实现），见[桌面时钟设计](home-clock.md)，输入时避免键盘与页面争抢滚动。

## 5. UE流程与导航

### 5.1 实体按键与返回

| 当前状态 | BOOT短按 | PWR短按 | 触摸 |
|---|---|---|---|
| 宠物页 | 打开设置 | 进入时钟 | 按页面已有交互处理 |
| 时钟页 | 打开设置 | 返回宠物 | 返回宠物 |
| 黑屏 | 唤醒并打开设置 | 唤醒回宠物 | 不唤醒 |
| 设置首页 | 退出回宠物 | 退出回宠物 | 点击设置项 |
| 设置子页 | 回设置首页 | 退出回宠物 | 返回图标与BOOT同义 |

这是当前实现：退出设置回宠物，不是恢复进入前页面。BOOT上电时按住仍进入芯片下载模式，不能与运行时短按混淆。PWR硬件长按关机行为不改。

新页面不得擅自改变按键含义。将来OTA安装期间如限制返回，必须明确显示阶段，并记录与上表的例外；不能声称软件能阻止断电或硬件长按关机。

### 5.2 反馈与等待

- 点击后给出按下反馈，避免用户猜测是否点中。
- 扫描、连接、下载须显示真实等待状态；耗时任务不阻塞触摸与动画线程。
- 防止重复提交，忙时禁用相关操作或解释为何暂不可用。
- 连接成功与保存成功分别判断，不能保存失败还显示“下次自动连接”。
- 区分取消、返回和退出。只有真正停止任务时才写“取消”；当前离开连接页不保证后台连接停止，不能冒称取消成功。
- 为错误、空列表、断网、超时和重试提供明确路径；不让用户卡在没有出口的页面。

## 6. 输入与Wi-Fi

当前流程：设置 → 网络扫描列表 → 选择网络 → 输入密码 → 连接结果。手机辅助配网是历史探索方向，不是现有功能。

### 6.1 密码键盘必须项

- 支持小写、大写、数字、常见符号、额外符号、空格、删除和提交。
- 不提供与单行密码无关的换行输入。
- 初始密码隐藏；眼睛按钮可切换，隐藏圆点与明文都清楚可读。
- 输入框、光标、按键放大反馈与底部键均在可用区域，键盘不能遮住提交操作。
- 退出密码页清理页面中的密码；日志、截图测试、产品记录不用真实密码。
- 长度错误要显示可见提示，不能只改已有文字输入框的占位文案。
- 不因输入复杂密码而强迫用户切换到不相关的设置页面。

当前支持开放网络及WPA2/WPA3 Personal，密码8–63字符；企业认证、隐藏SSID和64位十六进制PSK未接入。界面须诚实反映支持范围，详见[Wi-Fi实现说明](../../firmware/WIFI_SETTINGS.md)。扫描、获取IP、保存凭据和重启重连分别验收，不能把一次“已连接”当作全部通过。

## 7. 亮度、息屏与陪伴体验

2026-10-12新增联网校时规则：每次Wi-Fi取得IP后进行一次有超时限制的后台SNTP校时，成功更新系统时间并写回RTC；失败保留原时间。网络页增加Wi-Fi开关，关闭保留凭据，开启重连；开机默认开启。校时成功与连接成功分别确认，不以Wi-Fi图标声称时间准确。实现及验收见[校时说明](../../firmware/TIME_SYNC.md)。

| 规则 | 当前基线 |
|---|---|
| 用户亮度 | 10–100%，默认50% |
| 调节 | 拖动实时预览，松手保存，重启恢复 |
| 作用页面 | 宠物与设置使用用户亮度 |
| 时钟亮度 | 10%，不随用户亮度设置变亮 |
| 黑屏亮度 | 0 |
| 宠物闲置 | 15秒进入时钟 |
| 时钟显示 | 60秒后黑屏，充电不延长 |
| 设置闲置 | 60秒退出回宠物，再按原闲置流程进入时钟与黑屏 |

不能将设置60秒超时描述成“立即息屏”，当前实现不是这样。亮度数字代表软件设置比例，不是已校准的亮度计测量值。100%已开放，满亮度供电稳定性与续航仍须真机验证。

AMOLED优先短时展示静态高亮内容；分钟移位是辅助措施，不能保证不烧屏。当前黑屏不是CPU深睡眠，不得以屏幕灭了声称达到深睡功耗。

2026-10-14电源策略：增加降频与黑屏自动轻睡眠配置，保留亮度/超时/按键规则；USB连接禁止自动轻睡眠。Wi-Fi默认保持连接，息屏停止作为独立持久化底层配置，受后台应用网络需求保护；用户设置开关待确认/待实现。电池真实唤醒与功耗待验收，见[电源管理](../../firmware/POWER_MANAGEMENT.md)。

宠物运动保持已确认的形象、比例、落点和自然节奏。新系统提示避免覆盖宠物脸部；设置页暂停宠物动画，退出恢复。背景随时间变化、点击太阳看时间等讨论方案尚未作为当前已实现行为。

## 8. OTA及未实现功能

当前“系统更新”仅为入口和待接入提示。下列是未来设计要求，不是已上线能力：

- 使用真实版本、更新内容和大小；无网络时提供配网路径。
- 区分检查、下载、校验、写入、重启和失败状态；只有获得真实数据才能显示百分比。
- 用户确认后安装，供电要求与电池阈值经硬件验证后确定。
- 写入期间防止重复更新，说明返回限制；明确断电和失败恢复方案。
- 保留宠物存档与用户设置，新版首次启动验证与回退需要实际实现和测试。

原型中的示例网络、演示成功和假版本号必须有演示标识，不能混入正式产品流程。

## 9. 开发与资源注意事项

- 尽量使用当前官方BSP和成熟LVGL控件；参考Demo后仍要适配本项目版本、尺寸与交互。
- 页面切换由UI线程执行；网络事件不要直接修改LVGL对象。
- 保留已验证的QSPI传输完成机制；固定竖屏不用多余的软件旋转缓冲，避免内部DMA内存不足。
- 素材采用无损压缩作为默认发布方式；压缩率、解压内存、加载寿命和帧率一起检查。
- 字体或资源增长后检查内部RAM、PSRAM、固件大小和分区余量；有32MB Flash不等于内部RAM充足。
- 数据保存成功后才能向用户承诺重启保留；频繁拖动等操作避免每个变化都写持久化存储。
- 设计错误修复要保存可恢复版本，走[发布流程](../../firmware/RELEASE_WORKFLOW.md)，不省略启动检查。

## 10. 每个页面的交付与验收

### 10.1 交付清单

每个新增或大改页面应给出：目的、入口/出口、默认状态、文字及主要操作、实体按键行为、等待/成功/失败/空状态、超时规则、保存语义、可见安全区及待验证事项。

### 10.2 必须检查

- [ ] 使用410×502实际尺寸及圆角遮罩检查，不只看方形大图。
- [ ] 返回按钮、固定底部操作和全部重要文字无物理裁切。
- [ ] 完整点击区域、焦点/按下状态、键盘弹出与放大反馈在安全范围内。
- [ ] 已输入密码的隐藏/显示两种状态均可读，长文字不遮挡相邻控件。
- [ ] 小字号、中文缺字、百分比、长SSID、空列表、错误信息均有检查。
- [ ] 连续输入、删除、大小写/数字/符号切换及触摸误触有真机检查。
- [ ] BOOT/PWR/返回、等待中返回、超时、黑屏唤醒符合明确定义。
- [ ] 保存、重启恢复、断网及重试分别核验；用户数据不被意外清除。
- [ ] 正式界面无性能叠字、假状态和未标注演示内容。
- [ ] 构建、压缩、刷写哈希、启动和人工功能验收分别记录。

### 10.3 状态与证据

“已编译”“已刷入”“启动通过”“视觉验收通过”“联网通过”“重启重连通过”不是同一状态。照片可证明当次显示情况，不能单独证明完整触摸区域、真实屏幕半径、持续稳定性或重启恢复。

用户2026-10-12照片证明一次网络连接结果及旧返回按钮裁切；安全区修复后已完成模拟检查、刷写和启动检查，真机边角改善仍待确认。不得在后续文档中直接升级为全面验收通过。
