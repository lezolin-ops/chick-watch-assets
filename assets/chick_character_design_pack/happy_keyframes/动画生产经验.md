# 开心动画生产：历史失误与经验沉淀

> 汇总 v1（2026-10-17 早）及更早轮次在关键帧、图生视频、GIF、模拟器接入中踩过的坑，供任何工具/人接力。新轮次开工前先读，避免重复犯错。

## 一、六类典型失误与规避

### 1. 比例不对 / 身体形变
- **失误**：蹬地帧被拉成瘦长（宽高比 0.654）、落地帧扁宽（1.077）、复位帧按瘦长保留，导致循环时 F6（瘦）→F1（圆胖）看起来整体大一圈。
- **原则**：身体全程等比，宽高比六帧一致；跳跃高低差由程序 `translate_y` 表达，**不靠把某帧拉长/压扁凑高低**。确需挤压时只改形状、横向撑开补偿纵向，视觉体积不变，且不整体缩放。

### 2. 颜色不统一
- **失误**：六帧身体黄饱和 0.61–0.68 偏奶白（母版约 0.783），腮红偏粉、背景纯白，与基准暖米白不一致。
- **原则**：以基准图取色写进提示词，定稿本地 HSV 拉齐，只动身体黄，腮红/喙/脚/眼/背景不改。基准色值（`00_front_reference.png` 实测）：
  - 身体黄 `#FDD649`、腮红 `#FEA879`、喙 `#FE8B28`、嘴内腔 `#F56432`、脚 `#FD8825`、背景 `#FEFCF4`。

### 3. 风格不统一
- **失误**：个别帧出现细描边、光影渐变、外轮廓亮边，偏离基准的扁平 2D 平涂。
- **原则**：提示词锁死"无描边、无渐变光影、无投影"；抠白底后用 alpha MinFilter(3) 收 1px 亮边，再缩放入画布。

### 4. 站位飘（脚与身体断开、悬空、不齐）
- **失误**：腾空帧把脚画在身体下方悬空，左右脚不在同一基线，水平中心左右晃。
- **原则**：静态关键帧双脚贴同一基线、水平居中；**腾空位移不画进静态帧**，由程序/序列帧自然偏移表达。序列帧接入时水平中心锁 x=96，只保留相对首帧的垂直跳跃偏移。

### 5. 翅膀与表情漂移
- **失误**：短三瓣小翅被画成大长翅/高举；笑眼帧误生成圆眼，嘴张合帧间跳变。
- **原则**：翅膀幅度写死"小角度、短三瓣、不拉长不高举"；每帧明确标注眼睛状态（圆眼+白高光 / 月牙闭眼弧线），生成后逐帧核对，错帧单独重抽，不整批重来。

### 6. 流程顺序颠倒（最关键）
- **失误**：先让 AI 图生视频，模型每帧重绘，颜色/比例/站位已经漂移，再压 GIF 救不回来。
- **原则**：**静态关键帧先验收（颜色/比例/站位/表情）→ 视频只做补间 → GIF 仅作方向预览，定稿走清晰 PNG**。GIF 的 256 色量化只影响预览，不进固件。

## 二、接入模拟器时的坑

- **双重跳**：跳跃已烤进序列帧时，demo 不要再叠加程序 `translate_y`，否则双跳。
- **图层遮挡**：AI 帧必须贴在与旧身体平级的独立图层（`s_demo_img`），贴到旧身体 `s_pet.img` 会被旧身体/眼层覆盖，画面停在底座。
- **头顶出框**：视频跳幅偏大时到顶帧呆毛贴边；192 画布头顶留 ≥25px 安全边距，跳幅收进留边内。
- **空档色差**：循环空档回旧程序化底座会与 AI 金黄帧有色差，空档可停在复位帧或缩短。

## 三、v2 已验证的生产链路（2026-10-17）

1. 基准图 `00_front_reference.png` 作唯一身份锚点，`image_edit` 逐帧衍生关键帧（身体等比、只改表情/翅膀小角度）；
2. 静态六帧对照验收 → 图生视频（seedance 2.0 fast，5s，1:1，单跳循环，身体不变形）；
3. 抽 12fps → 近白底+浅灰投影一起抠透明 → alpha MinFilter 1px → 192 画布（角色高 156、脚 y=179、中心 x=96，保留自然垂直跳幅）→ 抽稀 6fps/30 帧；
4. BGRA 字节序写 LVGL ARGB8888 C 描述符，`--happy-demo` 按时间选帧、不加程序位移；
5. GIF 全片共享调色板、先缩放再量化，仅预览不进固件。

脚本：`lvgl-simulator/tools/prepare_happy_seq_v2.py`。

## 四、v2 模拟器接入新增教训（2026-10-17）

### 7. 同一循环只允许一个来源，不要拼接不同质量的帧
- **失误**：曾把基准 F1（亮黄、精确）单独作为休息帧，循环开始再切到 AI 视频序列（偏暗、翅膀略小），用户看到"先一帧形象、然后跳到动画帧"的明显切换。
- **原则**：进入、空档、播放全程用同一来源的帧；要停就停序列自身首帧，不另插基准帧/旧底座。不同来源（基准 PNG vs AI 重绘视频帧）的色差和造型差，拼在一起就是跳变。

### 8. 腾空偏移方向别写反（跳成往下压）
- **失误**：抽帧归一化时把腾空帧的相对脚底偏移符号写反，到顶帧被往下压、脚底落到画布 201px（超出 192 底边被裁），看起来"特意被压一下"。
- **原则**：基准贴地脚 y=179；腾空帧脚在基准**上方**，`y = 179 + 相对偏移(负值) - 帧高`；每帧打印 top/bottom 核对，到顶帧脚底应明显高于 179。

### 9. 跳幅按视频自然幅度保留，不为安全边距压跳
- **原则**：用户明确跳起来出框不必限制；抽帧保留源片相对首帧的完整垂直跳幅，不缩放压缩、不强行收进头顶留边。安全边距是定稿 PNG 阶段的事，预览阶段先看动作幅度。

### 10. 序列素材从清晰母版抽，不从 GIF 抽
- **原则**：模拟器序列帧直接从 mp4 抽 PNG 再抠图转 C；GIF（256 色量化）只用于肉眼确认方向，任何环节都不回读 GIF 当素材。

### 11. 校色用整体增益/均值偏移，不要逐像素强制 H/S（2026-10-17 踩坑）
- **失误**：第一版身体黄校色把 mask 内每个像素的 H、S 强制设为基准值、再按均值缩放 V，结果平涂、高光过曝、mask 边缘把腮红/翅膀串色，用户反馈"失真了"。
- **正确做法**：按帧身体 mask 均值算逐通道增益（`out = pixel × 基准均值/帧均值`，clip 255），只把整体均值搬到基准色，保留每个像素自己的明暗渐变；mask 收紧（b<115、r-b>120）把腮红（b≈122）、喙、脚排除在外。
- **原则**：校色是"白平衡/整体提亮"，不是"重新填色"；动色不动形、动均值不动渐变。即便整体增益，AI 重绘帧的底子偏色仍可能让用户觉得失真——根本解法是不用视频像素当画面，见第 13 条。

### 12. 先定量再生成，别一上来拉满时长（省 token）
- **实测（开心 v2，5.08s/12fps=61 帧）**：真正在动的仅 f36–f46 约 1s，34/61 帧近静止，全是浪费；单跳类动作压到 1.5s 内足够。
- **原则**：生成前先用一句话估主动作时长（站立→蹬地→到顶→落地→复位），按最短成立时长选秒数，不为"5s 完整"凑静止段；同样的动作短视频 token 明显更少。

### 13. 省 token 首选"借动作不借画面"：倒推运动曲线 + 清晰关键帧程序补间
- **做法**：已确认样片只本地量运动曲线（起跳点/到顶/落地时间、跳幅 px、翅膀节拍），零额外生成；画面用已验收清晰关键帧，程序按曲线做垂直位移+帧切换补间。AI 视频只在需要全新动作灵感时用，且不复制它的像素。
- **为什么**：AI 图生视频逐帧重绘必然偏色/漂移，在它像素上校色只会反复失真；清晰关键帧身份颜色锁定，程序补间无重绘。
- **适用**：单主体、单一主动作（跳、点头、招手）的宠物循环；复杂多镜头表演仍可用 AI 视频定方向。

### 14. 循环跳变先查"是否拼了不同来源帧"，不要先怪视频接缝
- **实测**：AI 单源首尾身体色差仅 (1.8,2.4,1.8)，自身循环接缝很小；用户看到的"先一帧再跳动画"来自另插的 F1 休息帧/旧程序化底座。
- **原则**：进入、空档、播放全程只用同一来源帧；要停就停序列自身首帧，不拼基准帧、不回旧底座。
