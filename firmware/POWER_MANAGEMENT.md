# 续航优化、产品取舍与后续调优

2026-10-14（Asia/Shanghai）。设备：ESP32-S3-Touch-AMOLED-2.06。第一轮机制已实现；电池侧功耗及等时对比尚未实测。

## 1. 当前选择

优先消除黑屏后台工作、降低空闲CPU消耗；保留最高240MHz、亮度10～100%、原15秒进入时钟/时钟60秒黑屏及BOOT/PWR交互。**Wi-Fi默认保持连接**；息屏停Wi-Fi是独立持久化底层配置，用户可操作的设置开关尚未实现，留待用户确认。

用户授权自主优化、要求刷前备份；后续明确策略可配置、未来应用可快速调优、使用相同时间的修改前后比较，不做完整放电。已确认安装电池，容量未知，不填写假定容量或虚构增加的续航小时数。

## 4. 后续应用接入统一电源层

入口：`main/watch_power.h`。应用不得自行覆盖全局esp_pm设置或关闭共享Wi-Fi。

- `WATCH_POWER_CPU`：处理动画、计算/解码期间需要最高配置频率。
- `WATCH_POWER_AWAKE`：当前工作不允许轻睡眠，例如尚不能安全恢复的外设操作。
- `WATCH_POWER_NETWORK`：保护无线保持开启；不代表取得IP，不自动替应用开启网络。
- 创建一次客户端，仅在实际工作期间acquire；成功、失败、超时和取消最终都release；释放后才delete。
- 重复acquire/release返回错误，不额外累计锁；held时禁止delete。调用者不得并发删除仍被使用的句柄，不能在ISR调用。
- 客户端标识使用唯一的1～31字节名称。`watch_power_dump_clients()`打印需求、持有状态及持有毫秒数，便于定位新应用长期占用。

```c
watch_power_client_t job;
ESP_ERROR_CHECK(watch_power_client_create("download",
    WATCH_POWER_NETWORK | WATCH_POWER_CPU, &job));
/* 先由网络服务完成Wi-Fi开启/连接，再检查IP与业务可达性。 */
if(watch_power_client_acquire(job) == ESP_OK) {
    /* 有界任务；成功/错误/取消最终都进入release路径。 */
    watch_power_client_release(job);
}
watch_power_client_delete(job);
```

获取网络需求与自动停网入队使用同一互斥锁。若停网先入队，enabled已false，新的网络需求拒绝获取，应用应恢复网络后重试。两个应用持有需求时，必须都释放才允许按策略自动停网。用户手动关闭Wi-Fi仍优先，应用应处理连接中断。SNTP已接入网络需求保护，完成有界校时后释放。

客户端诊断只覆盖应用层需求，不等于系统全部电源锁。应用没有持有需求但仍不省电时，继续检查USB连接、Wi-Fi、SPI/I2S等驱动锁及周期计时；必要时启用IDF PM profiling做对照，测试后关闭。

新应用发布前检查：隐藏页面不持续刷新、不长期持最高CPU/禁止睡眠锁；新增驱动是否持有系统电源锁；退出、取消、失败是否释放；唤醒后资源是否恢复。模块初始化失败时自动停网禁用，优先安全回退。

### 息屏Wi-Fi配置

`watch_power_set_sleep_wifi_off(bool)`写入 `pet_power/sleep_wifi_off`；成功提交才改变运行策略，失败保持原值。`watch_power_sleep_wifi_off()`读取。无保存配置时默认false。

true：黑屏、没有联网应用需求时停网，重启仍启动联网，唤醒不自动重连，原网络页可手动开启。false：保持当前连接，但不会擅自重新开启用户已关闭的无线。未来设置界面应说明这个区别并提供网络开启入口。**底层接口已实现；用户设置开关待确认/待实现。**

## 5. 快速调优与分项构建

正式默认无损压缩素材、80～240MHz，各机制ON。工具目录先加入PATH，再加载IDF环境，避免idf.py使用错误Python。

```sh
export PATH=/Users/Zhuanz1/Documents/trae_projects/mini/tools/venv/bin:$PATH
source /Users/Zhuanz1/esp/esp-idf-5.4/export.sh
idf.py -C firmware -B build-power -D PET_PACK_RESOURCES=ON \
  -D WATCH_ENABLE_POWER_MANAGEMENT=ON \
  -D WATCH_OPT_DFS=ON -D WATCH_OPT_TICK=ON \
  -D WATCH_OPT_SCENE=ON -D WATCH_OPT_SLEEP=ON \
  -D WATCH_CPU_MIN_MHZ=80 -D WATCH_CPU_MAX_MHZ=240 build
```

| 参数 | 默认 | 独立实验 |
|---|---|---|
| WATCH_ENABLE_POWER_MANAGEMENT | ON | OFF复现优化前相关逻辑，仅用于对照 |
| WATCH_OPT_DFS | ON | OFF保持最低频率等于最高值 |
| WATCH_OPT_TICK | ON | OFF保留原5ms周期tick |
| WATCH_OPT_SCENE | ON | OFF保留隐藏云/风定时器 |
| WATCH_OPT_SLEEP | ON | OFF不自动轻睡眠，仍可降频 |
| WATCH_CPU_MIN_MHZ | 80 | 40/80；40为实验值，未验收 |
| WATCH_CPU_MAX_MHZ | 240 | 80/160/240；降低上限需测动画/触摸 |

测试后恢复全部默认，并核对CMakeCache/编译宏。基准开关是新工程的相关逻辑复现，不等于原备份逐字节版本。精准回退用匹配备份。调试日志/PM profiling/采样开销两组一致；正式固件不引入高频诊断日志。

IDF的S3 GPIO-reset workaround会在tickless模式选择 `PM_SLP_DISABLE_GPIO`，不能只把defaults设n便声称禁用。当前实现对GPIO0、4～15及38明确调用 `gpio_sleep_sel_dis`，保留显示/触摸复位、QSPI、共享I2C及按键输入状态。后续新增外设必须核对其睡眠引脚和驱动保持能力，不能因CPU睡眠支持就假定所有外设可无条件恢复。

## 6. 等时A/B：不做完整放电

默认每组10分钟，噪声大可选20～30分钟。同一设备、电池、相近起始电量与温度，相同亮度/屏幕状态/无线环境/操作次数；先稳定60秒，再开始窗口。**断开USB供电/充电**；插USB则该窗口作废，插拔造成的瞬时回弹不计入。

优先用电池侧电流记录仪，记录均值/峰值及电压。普通USB表测的是USB输入，不能直接当电池放电。仪表串联压降、采样频率和接线两组保持相同。今晚不要求用户拆电池，仪器与物理操作留到早上。

若只有AXP电压/百分比，记录起止各30秒的中位数、VBUS及充电状态；没有掉1%不等于没耗电，不能从电压下降比例换算小时数。这种方式只能给弱证据，不满足每项精确量化。

| 实验 | 相同场景 | 唯一改变 |
|---|---|---|
| A | 黑屏，关联同一路由器，默认保持连接 | 原基准 vs 第一轮组合 |
| B1 | 黑屏，其他机制相同 | 隐藏场景暂停开/关 |
| B2 | 黑屏，无线与其他机制相同 | DFS开/关 |
| B3 | 黑屏，其余相同 | 周期tick vs 真实时间tick |
| B4 | 黑屏，tick已优化，无线条件固定 | 自动轻睡眠开/关 |
| B5 | 黑屏、没有网络应用需求，其余相同 | 保持Wi-Fi vs 按策略停Wi-Fi |
| C | 每180秒PWR返回宠物，随后按原15/60秒超时，两组同节奏 | 组合前/后，同时验交互 |

先A确认组合，再优先B4/B5，B1～B3按需要补测；最后C回归。需要排除测试顺序偏差时A-B-B-A复测，不只选最好的一次。每项效果不是整块主板功耗减少量，必须用电池侧数据判断。

### 计算

有电流记录时：`I_avg=Σ(I×Δt)/ΣΔt`；节省比例 `1-I_new/I_old`；相同可用容量和使用模式下，条件性续航倍率约 `I_old/I_new`。电压差异较大还应比较 `Σ(V×I×Δt)`。这些是估算，不保证覆盖所有使用模式。

只有旧版同模式实际续航T已知，才估算增加时长 `T×(I_old/I_new-1)`。当前无实测T、容量也未知，**不编造小时数**。最终产品表列平均电流/耗能、同窗口电压/百分比、估算倍率、连接保持、唤醒延迟、证据可信度、采纳/可选/暂缓建议。

### 数据分析工具

`tools/compare_power_windows.py old.csv new.csv`读取列 `elapsed_s,battery_voltage_v,battery_current_ma,usb_connected`，电流以正值mA表示放电，窗口USB标志必须全部0。电流列可空，但此时只报告电压变化，不计算续航倍率；不输出未经测量的增加小时数。默认时长允许2秒采样边界误差，明显不等时拒绝比较。

工具按时间积分电流/耗能；`tests/power/window_analysis.py`使用明确的合成数据验证计算、USB拒绝和时长拒绝，**不是设备测试结果**。应用机制测试用 `sh firmware/tests/power/run.sh`，既有UI回归用 `sh firmware/tests/settings_ui/run.sh`。

采样CSV空模板为 `tests/power/window_template.csv`，没有填入任何虚构设备数据。

## 2026-10-14 离线超时策略

## 2026-10-14 重连退避

连续连接失败后，按每一轮结束计时，等待30秒→60秒→120秒→300秒，后续上限300秒。每轮仍最多尝试两次，不把两次内部尝试误称两轮。使用单调时钟，不受RTC/网络校时变化影响；等待由现有队列30秒检查执行，实际发起时间可稍晚，不额外创建任务或阻塞手动操作。

手动选择网络或手动重新开启Wi-Fi立即处理并重置退避；成功联网重置。手动刷新列表不清空已有退避进度，不用反复扫描绕过等待；刷新后无IP可继续按原截止时间重连。未保存网络不自行选择陌生网络。已取得IP不额外重连。

15分钟自动关闭配置及开机默认开启规则保留；超时检查每30秒进行，与重试截止时间独立，后台联网需求仍保护停止动作。此更新替代此前固定每30秒启动一轮的自动重连行为，不改变UI、不更改凭据或充电参数。

验证：纯策略测试覆盖全部阶梯、上限、截止前后、重置与独立关闭计时；现有电源需求保护测试通过。真实完整5分钟阶梯、人工联网恢复及耗电收益需单独验收；不能将重试次数减少比例当整机节电比例。
