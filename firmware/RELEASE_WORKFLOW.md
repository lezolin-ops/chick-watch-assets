# 固件发布标准流程

2026-10-12 用户确认后作为默认流程执行。

1. 阅读产品记录及FIRMWARE，核对当前变更、端口、实际Flash容量、分区布局与板级补丁。
2. 开启 `PET_PACK_RESOURCES=ON`；核对CMakeCache、主应用编译中的 `PET_USE_PACKED_ASSETS=1`、资源清单及固件大小。这里是无损LZ4素材压缩，不是把整个bin压成一个可直接运行的压缩包。
3. 编译通过，完成本次变更所需的有意义验证。UI变化须检查真实LVGL布局、相关交互及圆角遮罩/完整触摸目标安全区；依据见DISPLAY_SAFE_AREA。资源格式变化须验证解码和内存。既有无关警告不能冒充无警告构建。
4. 保护设备当前可恢复版本；确认备份与本机设备匹配并记录路径。已有匹配备份可以复用；无备份时先读取必要的固件与配置范围。含密码的备份不对外分享。
5. 优先应用分区烧录；启动程序/容量/分区改变时核对对应烧录范围与用户数据影响。使用esptool默认压缩传输，并确认每项哈希校验。
6. 重启采集日志，核验显示、内存、驱动、本次功能初始化，检查panic、abort和反复重启。下载模式烧录后如不能退出，拔插USB；进下载模式为断开USB、按住BOOT重新插USB，本板没有RESET键。
7. 验收用户可见行为。需要密码或物理触摸时由用户输入/操作；不索取或记录真实网络密码。真实联网、触摸和续航不能由模拟测试替代。
8. 出现启动异常先修复并复测；修复不能验证时明确说明，必要时恢复稳定备份。更新产品和技术记录，区分已编译、已刷入、启动通过、待人工验收。
